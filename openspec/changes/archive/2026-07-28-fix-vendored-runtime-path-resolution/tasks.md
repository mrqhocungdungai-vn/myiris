## 4. Initialization failure is visible

- [x] 4.1 Separate the two meanings `onError` currently carries. `src/hooks/useWakeWord.ts:243-246` reports a **non-fatal** microphone fallback (it re-acquires on System Default and arms successfully); `src/hooks/useWakeWord.ts:283-287` is the **fatal** init failure. Implemented naively, a user with an unplugged saved microphone gets a permanent "failed" affordance on a working listener. Either add a distinct `onInitFailed` callback or make it an explicit, commented rule that only an `onError` **without** a `fallbackDeviceId` sets the failed state (design D3)
- [x] 4.2 Add an `onReady()` callback to `useWakeWord`, fired after the prediction interval is installed at `src/hooks/useWakeWord.ts:280-282` and only when the effect has not been cancelled. Without it there is no success signal at all and the recovery scenario cannot be satisfied — clearing on the effect re-run clears on re-arm *attempt*, which flickers and then reappears (design D3)
- [x] 4.3 Hold the wake-word init error in `src/App.tsx` state instead of dropping it into `pushLog`, whose state is discarded at `src/App.tsx:90` and rendered by nothing. The existing `fallbackDeviceId` mic-fallback branch at `src/App.tsx:620-623` must keep working unchanged

- [x] 4.5 Make the failure visible in **both** caption surfaces — the deck at `src/App.tsx:1495-1496` and the HUD at `src/App.tsx:1602-1603` consume the same `caption`, so fixing one leaves the other still telling the user to say "Hey Iris". ## 5. End-to-end wake check (design D8)

- [x] 5.1 Add a script under `scripts/` that builds the fixture with `say "Hey Iris" -o …aiff` then `afconvert … -f WAVE -d LEI16@16000 -c 1` (16-bit LE PCM mono is required by Chromium's fake capture device — do not simplify to a default `afconvert` invocation), and pads it **in the script**: read the WAV, keep the 44-byte canonical header, prepend and append silence as zero samples, rewrite the two length fields. Neither `say` nor `afconvert` can generate silence or concatenate, and `sox` is not on stock macOS — do not burn time looking for a CLI that does this. Cache the result rather than regenerating per run
- [x] 5.2 Size the leading pad for two independent reasons, and comment both: the 2 s ring buffer must fill before the phrase arrives, and `src/App.tsx:589-591`'s async `getConfig()` must land first because the pass token at `src/hooks/useWakeWord.ts:198` is gated on `settings.debug`, which arrives with that config. Note also that `--use-file-for-fake-audio-capture` **loops** its input by default (`%noloop` disables it), so the trailing pad is what keeps the looped clip from reading as `"Hey IrisHey Iris"`
- [x] 5.3 Have the script launch with `--use-fake-device-for-media-stream`, `--use-file-for-fake-audio-capture=<fixture>`, `--no-sandbox`, and a throwaway `--user-data-dir`, under `IRIS_START_PROD=1 IRIS_WAKE_WORD=true IRIS_WAKE_DEBUG=1 IRIS_WAKE_THRESHOLD=0.15 IRIS_WAKE_CONSECUTIVE=2`. Pinning the last two is required, not tidiness: `electron/user-config.mjs:26` gives CLI env precedence over `.env`, and `src/components/SetupPanel.tsx:81-82` writes `IRIS_WAKE_THRESHOLD` into `.env` on every settings save, so an unpinned check fails red for anyone on the Strict preset
- [x] 5.4 Guard build freshness inside the script: either run `npm run build` itself, or hard-fail when `dist/index.html` is missing or older than `src/`. `electron/window.mjs:94` loads whatever is on disk, so a script that launches without rebuilding passes green against a pre-fix bundle — the exact silent pass this check exists to prevent
- [x] 5.5 Attach the `console-message` listener on the window's `webContents` in `electron/window.mjs`, inside the existing `if (envFlag("IRIS_WAKE_DEBUG", false))` branch at `electron/window.mjs:100` that already opens DevTools for this diagnostic. Use Electron 42's **single-object** signature — `(details) => …` carrying `message`/`level`/`lineNumber`/`sourceId`, **not** the widely-documented `(event, level, message, line, sourceId)` form, which yields `undefined` and surfaces as a timeout with a misleading cause. Do **not** put it in the script: `scripts/` is covered by no typecheck (root `tsconfig.json` includes only `src`, `tsconfig.electron.json` only `electron/**`), so a wrong signature there compiles fine and fails at runtime. Do **not** create a new `electron/*.mjs` that imports Electron: `electron-graph.supply.test.mjs:29` hardcodes the four permitted modules and asserts exact set equality at line 65, so a fifth fails `npm test`
- [x] 5.6 Assert on the forwarded console output: pass on `[wakeword] fired`, fail on `[wakeword] init failed`, fail on a timeout with neither
- [x] 5.7 Make the script exit non-zero on failure, terminate the Electron process tree on every path including timeout, and clean up its `--user-data-dir`
- [x] 5.8 Confirm the script is **not** wired into `npm test` — it boots Electron, which the test-harness spec forbids there — and document how to run it
- [x] 5.9 Prove the check is red-capable, **rebuilding on both legs**: restore the relative path from task 2.1 → `npm run build` → run the script → confirm it fails; restore the fix → `npm run build` → run → confirm it passes. Skipping either rebuild produces green-then-green and the wrong conclusion that the check is broken. A check that has only ever been green is not evidence
- [x] 5.10 Confirm `--no-sandbox` appears only in the script's own `spawn` argv and nowhere under `electron/`; `webPreferences.sandbox: true` at `electron/window.mjs:88` is what the app ships and this change does not touch it. Note the check itself does **not** run sandboxed regardless of that line, since the switch disables it for the launched process tree — the checkable invariant is about the argv, not about the source line
