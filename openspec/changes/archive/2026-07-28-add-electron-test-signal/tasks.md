## 3. Import-graph test — supply side, under the native loader

- [x] 3.1 Restructure `vitest.config.mjs` into **two explicit projects**. "Add a project without touching the global config" is not achievable and an earlier draft of this task wrongly said it was: the file is a single config whose root-level `test` options cover both directories, and in Vitest 4 root-level options are **not** inherited by projects.
  - The existing `server.deps.inline: ["@excalidraw/excalidraw", "roughjs"]` is load-bearing and must be replicated into the default project. Its comment explains why: excalidraw ships an extensionless deep import (`roughjs/bin/rough`) that **Node's native ESM resolver rejects**, so `canvas-mcp.golden.test.mjs` needs Vite's resolver.
  - The graph project needs the exact opposite — `server.deps.external` matching `electron/**/*.mjs` so modules load through Node's native loader. These two settings are genuinely opposed, which is why they must be separate projects rather than one merged config.
  - Comment both, stating that undoing the externalization silently restores the masking with no test failing.
- [x] 3.1b Put the graph test's config **outside `electron/`**. `package.json`'s `build.files` globs `electron/**` and excludes only `*.test.mjs`, so any other file dropped there ships inside the packaged app. Repo root alongside `vitest.config.mjs` is the right home. Confirm `canvas-mcp.golden.test.mjs` still passes after the restructure — it is the canary for the `inline` setting.
