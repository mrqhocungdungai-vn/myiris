## Why

`second-brain-galaxy-view` (change #1, now archived) shipped the 3D vault galaxy and its note reader as **mouse-only** — clicking a node opens it, and a trackpad drives the camera. The whole point of the galaxy living in the Glass HUD, though, is hands-free "fly through your second brain": the roadmap always framed gesture control (open / orbit / zoom / close by hand) as the second half of the feature, deliberately deferred so change #1 could land the render + data layers first. This change adds that gesture layer.

## What Changes

- **Point-and-dwell to open a node.** With hand control on and the galaxy active, holding the pointing hand over a node for the same 300 ms dwell used everywhere else in the HUD opens that note — the galaxy's WebGL nodes are not DOM elements, so this is a new screen-projection hit-test — node positions projected against the graph's own camera, with a front-of-camera guard — not the existing `document.elementFromPoint` dwell (which stays suppressed while the galaxy owns the surface, apart from the HUD control island). Ghost nodes are not dwell-openable, exactly as they are not click-openable.
- **Fist orbits the camera, pinch zooms it.** In the galaxy context a closed fist's movement delta orbits the camera around the graph, and thumb-index pinch distance dollies in/out — driven through the library's `camera()`/`cameraPosition()` on spherical coordinates the renderer owns. Mouse drag/scroll keep working.
- **The note reader gains its gesture bindings.** `NoteReader` currently passes `hand={null}` into the shared `ReaderCore`; this change feeds it real hand state so the reader's already-built fist-close / two-open-palms-resize / open-palm-scroll bindings light up for vault notes exactly as they do for the task reader.
- **A single authoritative gesture-context map**, derived from one shared pure resolver (`src/lib/gestureContext.ts`) rather than another hand-written guard. Reader open → reader gestures only (galaxy nav and node-dwell suppressed); galaxy active, no reader → galaxy nav + node-dwell (orb and deck bindings already suppressed); neither → the existing deck behavior. The HUD control island stays dwell-activatable under the galaxy so the layer has a hands-free exit, and the gesture action indicator is extended to name the binding that is actually live (today it would report "idle" while a fist orbits the camera). The resolver is adopted only in the code this change touches; the three shipped deck loops keep their guards, with the remaining duplication recorded as follow-up debt.
- **The subtle logic is pure and unit-tested.** Hit-test (including the behind-camera rejection), the dwell state machine, the pose partition, and the camera step live in `src/lib/galaxy-nav.ts` with tests — matching `src/lib/hand.ts`/`downsample.ts` and change #1's extracted parser — so the riskiest corrections are verified headlessly instead of only by waving a hand at a webcam.
- **A change-#1 lifecycle bug is fixed** (filed under `second-brain-galaxy-view`, not this capability): the galaxy is not cleared when the HUD is exited by hotkey/tray, which can leave a note reader mounted over the deck; the reader's existence becomes derived from the galaxy's so no close path or in-flight fetch can strand it.
- **No new dependencies.** Everything is built on `3d-force-graph`/`three` (from change #1) and the existing `useHandControl` MediaPipe hook. Gesture control stays gated on the existing opt-in hand-control toggle — with it off, the galaxy is mouse-only exactly as change #1 shipped.

## Capabilities

### New Capabilities

- `second-brain-gesture-nav`: hands-free control of the second-brain galaxy — point-and-dwell to open a node, fist-orbit and pinch-zoom the camera, the note reader's gesture bindings, and the galaxy-vs-reader gesture arbitration.

### Modified Capabilities

- `two-hand-gestures`: **three** requirements are amended. "Fist rotates and pinch scales the orb", "Universal point-and-hold click", and "Two-palm reader resize" all gain the "not while a fullscreen HUD layer is active" clause — this makes room for the new galaxy bindings *and* reconciles all three with the suppression already in code (the 2026-07-24 orb-leak bugfix gated all three loops on `!drawingActive && !secondBrainActive`, but only the orb requirement was ever considered; the other two still read as unqualified, which the new capability's suppression scenario would otherwise directly contradict once archived). The dwell requirement additionally carves out the HUD control island so a fullscreen layer can be closed hands-free, the reader requirement is generalized from "the reader overlay" to either reader (the bindings live in the shared reader core, and this change gives the vault note reader the same ones) and gains the "per-frame gesture work only while hand control is enabled" footprint clause, and the orb requirement gains the "action indicator names the live binding" clause.
- `second-brain-galaxy-view`: the galaxy layer's own lifecycle requirements are corrected — the galaxy is stated to be HUD-only and cleared on **every** HUD exit (the hotkey/tray path clears the drawing panel but not the galaxy today), the note reader's existence is tied to the galaxy's by construction (so no close path or in-flight note fetch can strand a reader over the transparent HUD or the deck), and the idle-pause signal is stated as sleep-only to match the code and `orb-expressions` (the shipped text says "or loses focus"). These are galaxy-layer facts, not gesture facts, so they belong here rather than in the new capability — and they must not be reverted along with a gesture rollback.

## Impact

- **Code — renderer only, no main-process or IPC changes.**
  - `src/components/VaultGalaxy.tsx` — `GalaxyCanvas` gains a gesture rAF loop that is only scheduled while `handControl && running` (it respects the same HUD-idle pause as the render loop and costs nothing when gestures are off), is self-guarded in try/catch → `onForceClose`, reads the hoisted per-frame hand ref, and drives node-dwell via a front-of-camera-guarded projection plus camera orbit/zoom via `cameraPosition`; new props thread `handRef` / `handControl` / `readerOpen` in (`running` already exists).
  - `src/components/HudShell.tsx` — the real parent of `VaultGalaxy` (App renders `HudShell`, not `VaultGalaxy` directly). `hand`/`handControl`/`handRef` already reach `HudShell` but stop there; this change extends `HudShell`'s prop surface to forward `handRef`/`handControl`/`readerOpen` to `VaultGalaxy`.
  - `src/components/NoteReader.tsx` — add `hand`/`handRef` props (today only `{title, markdown, onClose}`) and pass them into `ReaderCore`, gated `hand={handControl ? hand : null}` (mirroring `ReaderOverlay`), plus the gesture footer hint.
  - `src/App.tsx` — thread `liveHandRef` / `handControl` / `readerOpen` into `HudShell`→`VaultGalaxy`; pass `hand`/`handRef`/`handControl` into the App-level `<NoteReader>` call site and render it as `secondBrainActive && openNote` *and* keep an effect clearing `openNote` when `secondBrainActive` falls (the two solve different halves — see design D7); clear `secondBrainActive` in `onHudMode`'s to-deck branch alongside `drawingActive`; extend the `handAction` memo with galaxy labels; exempt `.hud-controls` from the universal dwell loop's fullscreen-layer suppression.
  - `src/components/ReaderCore.tsx` — one small change: a `gesturesEnabled` prop in the gesture loop's dep array so no rAF is scheduled when hand control is off (its loop is `useEffect(…, [])` today and would otherwise spin over an empty hand ref). Binding logic untouched.
  - **New pure modules:** `src/lib/galaxy-nav.ts` (hit-test, dwell state machine, pose partition, orbit/zoom math) and `src/lib/gestureContext.ts` (the context resolver), each with a vitest file — matching `src/lib/hand.ts`/`downsample.ts`/`tasks.ts` and change #1's `electron/vault-graph-parse.mjs`.
- **No new npm dependencies**, no new IPC channels, no persisted state, no env flags. `3d-force-graph`'s `camera` / `cameraPosition` / `controls` / `onEngineStop` are already part of the pinned `1.80.0` API, and the projection uses `three`'s own `Vector3.project` (the library's `graph2ScreenCoords` helper is deliberately **not** used — it does no visibility test, see design D1).
- **Spec:** new `second-brain-gesture-nav` capability; deltas to `two-hand-gestures` (three requirements) and `second-brain-galaxy-view` (three requirements).
