## 2. Pure policy modules + tests (no spike dependency)

- [x] 2.1 Create `src/lib/galaxy-nav.ts` (pure — no React, no DOM, no `fg`), owning a module-level scratch `THREE.Vector3` so callers never pass one (M12/M-2):
  - `nearestNodeAt(nodes, camera, rect, point, thresholdPx)` — projects with the module scratch, **accepts a node only when its projected `z` satisfies `-1 ≤ z ≤ 1`** (accept-form, not a reject-form: a point at the camera projects to `NaN/NaN/-Infinity` and every NaN comparison is false, so only the accept test excludes it — L15), applies the `rect` offset, skips ghost and position-less nodes, returns the nearest survivor or null.
  - `dwellStep(state, candidate, now, holdMs)` → `{ state, target, fire }` — the 300 ms + leave-and-re-acquire contract, **plus** a dead-band/hold before a new candidate is committed as the target (M14: committing a target re-assigns `nodeColor`, which re-runs the whole node digest with per-node material dispose/allocate; an uncontrolled target flip in a dense cluster would mean up to 60 full-graph digests/sec).
  - `driveFor(hand)` → `"dwell" | "orbit" | "zoom" | null` — `Pointing_Up` → dwell, `Closed_Fist` → orbit, an **explicit pinch predicate** (single tracked hand, not `openPalm`, `pinchDistance` below an engage threshold, released above a larger one — hysteresis) → zoom, **`null` for everything else**. Zoom must NOT be the leftover `else` branch (H3): MediaPipe publishes no pinch class, so "otherwise" would let an open palm, an unrecognized pose, or a hand resting in frame drive the camera.
  - `orbitStep(spherical, delta, sensitivity)` and `radiusStep(radius, pinchDelta, sensitivity, min, max)` — both **relative**, so each drive seeds a reference on engage and applies deltas after (H3: an absolute `pinch → radius` map would snap the camera the instant the pose engages, contradicting the no-jump rule).
- [x] 2.2 Create `src/lib/galaxy-nav.test.ts`: a node in front vs. behind the camera (build a real `THREE.PerspectiveCamera` + `updateMatrixWorld()` — no WebGL context needed; verified this runs under the repo's `environment: "node"` vitest config) asserts only the front one is targeted, and a node *at* the camera is excluded; ghost/position-less nodes are skipped; the container offset is applied; the dwell machine fires once at 300 ms, not again until the target is left and re-acquired, and does not commit a jittering candidate before the dead-band/hold elapses; `driveFor` returns exactly one drive per pose, `null` for open-palm/two-palms/unrecognized, and hysteresis prevents chatter at the pinch boundary; `radiusStep` clamps at both ends.
