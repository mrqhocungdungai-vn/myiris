## 3. Tools over the canvas cache

- [x] 3.1 `get_canvas({ includeImage? })` — return main's in-RAM cache (canonical excalidraw JSON), fresh-on-call, works while the panel is unmounted. `canvas-store.getScene()` returns **`null`** on a fresh machine — treat `null` as an empty scene, never crash. For `includeImage`: **main never imports excalidraw** (its build entry pulls `roughjs` and touches `window`/`document`). When the panel is mounted, request an export from the renderer over a **request/response IPC** — `canvas:request-image` (main→renderer, carries a correlation id) → renderer exports via `exportToBlob`/`exportToSvg` → replies on `canvas:image-result`; main resolves a pending-promise registry keyed by the id, with a **timeout** so a mid-teardown panel can't hang the tool. On timeout or when unmounted, **degrade to JSON-only** (omit the image), never a tool error.
- [x] 3.2 `add_elements` / `update_elements` / `delete_elements` — mutate the cache by element `id` (last-writer-wins; see D4) via **read-modify-write** (`getScene()` — treat `null` as empty — → transform whole scene → `setScene(next)`; there is no by-id store API). New elements from `add_elements` are expanded from Claude's skeleton by a **pure main-side element builder** (NOT `convertToExcalidrawElements`, which can't run in main) that fills every required excalidraw field (`id,type,x,y,width,height,angle,strokeColor,backgroundColor,fillStyle,strokeWidth,roughness,opacity,seed,version,versionNonce,updated,groupIds,boundElements,…`) — incomplete elements are silently dropped by excalidraw. Each tool returns a **per-element result** (`applied` / `skipped: unknown-id` / `rebound: dropped-binding`); arrow `startBinding`/`endBinding` validated against the union of the cache and the current add batch. Persist via the change-1 async atomic write and **force a `flush()` after each write** (Claude writes carry a higher durability expectation than user strokes). When the panel is mounted, broadcast `canvas:apply` carrying the **FULL post-write element set** (not a delta — see task 4.2).

- [x] 4.2 In **`src/components/DrawingCanvas.tsx`** (register inside its effect so the handler's lifetime equals "panel mounted" — the panel is unmounted whenever closed, which is exactly what makes an image request time out → JSON-only), on `canvas:apply` call excalidraw `updateScene({ elements })` with the **FULL element set** the payload carries — `updateScene` *replaces* the whole array, so a partial payload would delete every user element. Do **not** re-run `convertToExcalidrawElements` (main already built complete elements — D5). Pass `captureUpdate: CaptureUpdateAction.NEVER` so Claude writes don't pollute the user's undo stack. **Suppress the `canvas:scene` echo** this apply's `onChange` would fire — use a robust guard (diff the `onChange` scene against the just-applied set, or a scene-version/nonce compare), **not** a one-shot "skip-next-onChange" boolean (`updateScene` may fire `onChange` zero times — leaving the flag armed to swallow the next real user edit — or more than once). User-originated edits still flow up normally.
- [x] 4.3 In **`DrawingCanvas.tsx`** (same effect, same mount-scoped lifetime), handle `canvas:request-image`: export the current scene (`exportToBlob` PNG / `exportToSvg`) and reply on `canvas:image-result` with the correlation id.
