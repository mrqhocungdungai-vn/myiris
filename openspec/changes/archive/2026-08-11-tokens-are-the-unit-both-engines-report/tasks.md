## 1. The ledger (pure, Electron-free)

- [x] 1.1 New `electron/token-ledger.mjs` — `createTokenLedger({ now, onChange })`, Electron-free and timer-free (the throttle belongs to the capability, task 2.1). Holds two accounts, `gemini` and `claude`, each `{ total, last, at }` plus Claude's `cacheRead`, and returns `snapshot()` giving flat, structured-clone-trivial scalars. `at` is load-bearing beyond display: it is the **event signal** the alert in section 5 detects a new run by, so it must be the time that account last changed and must not be rewritten when nothing changed. **Every absence is `null`**, on the same rule `system-telemetry.mjs` states in its header — an engine that has reported nothing has `total: null`, not `0` (spec: "Nothing that has reported nothing reads as zero")
- [x] 1.2 `recordGeminiUsage(usageMetadata)` implementing design D3's dual-regime accumulator: keep `lastTotal` and `carried`; a reading `>= lastTotal` is cumulative (`total = carried + reading`), a reading `< lastTotal` is a restart or per-message (`carried += lastTotal`, then as above). Read `totalTokenCount` when present, else sum `promptTokenCount + responseTokenCount + thoughtsTokenCount + toolUsePromptTokenCount` defensively (missing key ⇒ 0, never `NaN`). Ignore a message with no numeric figure at all rather than recording a zero
- [x] 1.3 `recordClaudeRun(run)` taking a run record and reading `run.usage.usage` (the SDK's passthrough of the API shape — note `runUsageFrom` in `electron/claude-stream.mjs:88` nests it one level under `usage`). Headline delta = `input_tokens + output_tokens + cache_creation_input_tokens`; `cache_read_input_tokens` accumulates into its own figure (design D5). **Idempotent by `run.run_id`** — a `Set` of counted ids, so a second observation of the same run cannot double it (spec: "One unit of work counts once"). No usage on the run ⇒ no-op, no id recorded
- [x] 1.4 Both totals monotone by construction — add an assertion-style guard in the tests rather than in the code path, since D3's arithmetic already makes a decrease unreachable and a clamp would hide a real regression
- [x] 1.5 `electron/token-ledger.test.mjs`: a cumulative Gemini stream is not summed; a per-message stream is; a mid-session restart to a lower reading keeps the total and continues growing (this is the Live-reconnect case and the most important test in the file); the same run recorded twice counts once, **and does not move `claude.at`** (or the alert would fire twice for one run); a run with `status: failed` / `limited` / `unanswered` still counts (spec: "Work that ended badly is counted too"); a never-used engine snapshots `null`, and an engine that reported a countable zero snapshots `0`; cache-read never enters the headline
- [x] 1.6 Log one line per counted Claude run and one per Gemini session close, `console.log("[IRIS][tokens] …")` so the existing tee picks it up (design D9). Nothing else is written to disk — no session store, no vault
