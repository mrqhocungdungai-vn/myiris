## Notes from implementation

Things the plan did not anticipate, found while carrying it out and fixed in place:

- **Three stale comments naming the old path or the old app name**, none of which any gate would ever catch: `electron/run-sessions.mjs:18` (`~/.iris/claude-home`, and it pointed at `worker-env.mjs` for a value that had moved to `app-paths.mjs`), `electron/user-config.mjs:16` (`a packaged Iris.app`), and `electron/mac-install-target.mjs`'s `resolveSourceBundle` docblock (`release/mac/Iris.app`). Comments are where a rename rots invisibly.
- **`electron/bundled-binaries.test.mjs`** used `/Applications/Iris.app/...` as its asar-path fixtures. Nothing under test depends on the name, so the tests passed either way — they were simply describing a bundle that no longer exists. Updated for honesty, not for correctness.
- **`LEGACY_INSTALLED_APP_PATH`** was added to `mac-install-target.mjs` so task 4.3's note can name `/Applications/Iris.app` from one tested place, with a test asserting it stays distinct from `INSTALLED_APP_PATH` — if the two ever converged, the "delete your old app" note would fire after every successful install and tell the user to delete what was just built.
- **`scripts/install-mac.mjs` needed more than the closing note.** Twelve log and failure lines hard-coded `Iris` — the messages a user reads while a directory in `/Applications` is being replaced. All now derive from `PRODUCT_NAME`; the file contains no `Iris` literal at all.
- **The migration was built, then deleted.** `electron/state-root-migration.mjs` and its test existed and passed — a marker-gated `renameSync` plus a transcript-slug repair — before the premise was corrected: this app has no released build, so there was never any user data under `~/.iris` to carry across. Removing it took out the only code in the change that could destroy data, a startup-path dependency, and a marker heuristic whose correctness rested on a survey of upstream's current `main`. Recorded because the deletion is the decision, not an omission (design D3).
- **`spec:check` cannot detect a stale path in the living spec** — see the note on 2.6. Worth knowing before relying on it as a safety net for a rename.
- **The tray's `"Quit Iris"` label had to move after all.** It was first left alone as persona copy, on the reasoning that `role: "quit"` makes macOS render the registered name. That is true only for the application menu, which passes a bare `{ role: "quit" }`; an explicit `label` on a **tray** item wins, so the tooltip would have read `MyIris` with `Quit Iris` immediately below it.
